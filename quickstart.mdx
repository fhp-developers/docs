This guide walks you through authenticating, finding a product, placing an order, and
retrieving your codes. Start in the [sandbox](/concepts/sandbox) with a `kal_test_…` key.

<Steps>
  <Step title="Get your API key">
    Your Kalixo account manager issues a sandbox and a production key, and whitelists your
    egress IP addresses. Keep keys secret and send them in the `x-api-key` header on every
    request. See [Authentication](/authentication).

    <Tip>
      Using **Postman**? Import the
      <a href="/kalixo-api-v2.postman_collection.json" download="kalixo-api-v2.postman_collection.json">Kalixo API v2 collection</a> and an environment
      ([Sandbox](/kalixo-api-v2.postman_environment.sandbox.json) or
      [Production](/kalixo-api-v2.postman_environment.production.json)), then set your `apiKey`
      variable. For local dev against split services, use the
      [Local environment](/kalixo-api-v2.postman_environment.local.json).
    </Tip>
  </Step>

  <Step title="Verify connectivity (optional)">
    Once your key is issued and your IP is whitelisted, confirm the API is reachable:

    ```bash cURL
    curl -X GET "https://sandbox.kalixo.io/v2/ping" \
      -H "x-api-key: $KALIXO_API_KEY"
    ```

    A `200` response with `{ "status": "ok", "timestamp": "..." }` means the API is up.
  </Step>

  <Step title="Find a product in your catalog">
    List your catalog and pick a row. Each row is one product in one country (market):

    - `productCode`: a stable 14-digit catalog identifier, identical in sandbox and production.
    - `countryCode`: the market of this row. You send it as `country` when you order.
    - `availableCountries`: every market the product can be ordered for. A regional product
      appears once per country, with the same `productCode`.

    Filter by country, brand, category, and more.

    <CodeGroup>

    ```bash cURL
    curl -X GET "https://sandbox.kalixo.io/v2/catalog/products?country=GB&take=5" \
      -H "x-api-key: $KALIXO_API_KEY"
    ```

    ```javascript Node
    const res = await fetch(
      "https://sandbox.kalixo.io/v2/catalog/products?country=GB&take=5",
      { headers: { "x-api-key": process.env.KALIXO_API_KEY } }
    );
    const { products } = await res.json();
    const { productCode, countryCode, price, currencyCode } = products[0];
    ```

    ```python Python
    import os, requests

    res = requests.get(
        "https://sandbox.kalixo.io/v2/catalog/products",
        params={"country": "GB", "take": 5},
        headers={"x-api-key": os.environ["KALIXO_API_KEY"]},
    )
    product = res.json()["products"][0]
    ```

    </CodeGroup>
  </Step>

  <Step title="Place an order">
    For each line, send the `productCode`, the row's `countryCode` as `country`, the **unit**
    `price` and the `quantity`. Add a unique `externalOrderCode` for the order. Prices are in
    minor units: `10000` is GBP 100.00.

    - `country` is required when the product's `availableCountries` has more than one entry.
      Sending it on every line is always safe.
    - The optional top-level `price` is the **order total**. If you send it, it must equal the
      sum of `(line price × quantity)`.
    - `externalOrderCode` is your idempotency key: a retry with the same code returns the
      existing order instead of creating a second one. See [Idempotency](/concepts/idempotency).

    The order is accepted immediately (`202`) with `processing`, `estimatedReadyAt`, and a
    `wallet` snapshot.

    <CodeGroup>

    ```bash cURL
    curl -X POST "https://sandbox.kalixo.io/v2/orders" \
      -H "x-api-key: $KALIXO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "externalOrderCode": "O-12345",
        "currency": "GBP",
        "price": 10000,
        "orderProducts": [
          { "productCode": "10020000213575", "country": "GB", "price": 10000, "quantity": 1 }
        ]
      }'
    ```

    ```bash cURL - regional product (EUR 100.00)
    curl -X POST "https://sandbox.kalixo.io/v2/orders" \
      -H "x-api-key: $KALIXO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "externalOrderCode": "O-12346",
        "currency": "EUR",
        "orderProducts": [
          { "productCode": "10001000227724", "country": "DE", "price": 5000, "quantity": 2 }
        ]
      }'
    ```

    ```javascript Node
    const res = await fetch("https://sandbox.kalixo.io/v2/orders", {
      method: "POST",
      headers: {
        "x-api-key": process.env.KALIXO_API_KEY,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        externalOrderCode: "O-12345",
        currency: currencyCode,
        orderProducts: [{ productCode, country: countryCode, price, quantity: 1 }],
      }),
    });
    console.log(res.status, await res.json()); // 202
    ```

    </CodeGroup>

    ```json Response (202)
    {
      "orderId": "b9f6f9a2-4d0a-4f5c-9a1e-7c2d8f3b6e10",
      "externalOrderCode": "O-12345",
      "status": "processing",
      "estimatedReadyAt": "2026-06-02T11:05:00Z",
      "wallet": { "balances": { "GBP": 196.01 }, "lowBalance": false }
    }
    ```

    <Warning>
      Leaving out `country` for a product with several markets fails with `400`:
      `Product 10001000227724 is available in multiple countries (DE, FR, IT); pass country (or a market sku) on the line`.
    </Warning>
  </Step>

  <Step title="Poll until a terminal status">
    After `estimatedReadyAt`, fetch the order by `orderId` or `externalOrderCode`. Codes are
    returned when the status is `completed` (every unit) or `partially_completed` (the
    delivered units).

    ```bash cURL
    curl -X GET "https://sandbox.kalixo.io/v2/orders/O-12345" \
      -H "x-api-key: $KALIXO_API_KEY"
    ```

    ```json Response (completed)
    {
      "orderId": "b9f6f9a2-4d0a-4f5c-9a1e-7c2d8f3b6e10",
      "externalOrderCode": "O-12345",
      "status": "completed",
      "products": [
        {
          "productCode": "10020000213575",
          "price": 10000,
          "quantity": 1,
          "codes": [{ "code": "ABCDE-FGHIJ-KLMNO-PQRST-UVWXY" }]
        }
      ],
      "wallet": { "balances": { "GBP": 96.01 }, "lowBalance": false }
    }
    ```

    <Tip>
      While the order is still working you get `"status": "processing"` and
      `"message": "Order is still processing"`. Wait until `estimatedReadyAt` before polling.
      See the [polling example](/concepts/order-lifecycle#polling-example), what to do with a
      [partial delivery](/concepts/order-lifecycle#partial-deliveries), or use the
      [Node reference client](/examples/kalixo-node).
    </Tip>
  </Step>
</Steps>

When you go live, switch the base URL to `https://api.kalixo.io/v2` and use your
`kal_live_…` key. productCodes are the same in both environments.
