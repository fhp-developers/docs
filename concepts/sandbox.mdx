Use the **sandbox** environment to build and test your integration before switching to
production keys.

## Environments

| | Sandbox | Production |
| --- | --- | --- |
| Base URL | `https://sandbox.kalixo.io/v2` | `https://api.kalixo.io/v2` |
| API key prefix | `kal_test_…` | `kal_live_…` |

See [Authentication](/authentication) for how to send your key.

## How it works

1. **Catalog** - Your assigned products are listed **plus** Kalixo Test products
   (brand **Kalixo Test**, field `isSandboxProduct: true`). Test products are
   included automatically - you do not need to request them separately.
2. **Orders** - Same `POST /v2/orders` and `GET /v2/orders/{reference}` flow as
   production, including price validation, wallet balances on responses, and
   balance debits when wallet ordering is enabled for your account.
3. **Codes** - Orders return test redemption codes prefixed with `SANDBOX-`. No
   real inventory is purchased and no live provider fulfilment occurs.

## Kalixo Test products

Each test product triggers one outcome, so you can exercise every branch of your
integration:

| Product | Price | Expected outcome |
| --- | --- | --- |
| Kalixo Test - Success (Fixed) | 499 | `completed` with one `SANDBOX-…` code per unit |
| Kalixo Test - Success (Open) | 500 to 50000, step 100 | `completed`; send the line `price` |
| Kalixo Test - Async Failure | 499 | `failed`, no codes |
| Kalixo Test - Partial Completion | 499 | `partially_completed` when quantity ≥ 2 (odd units succeed) |
| Kalixo Test - Slow Processing | 499 | `processing` for about 10 seconds, then `completed` |

Prices are in minor units (`499` is GBP 4.99). Every scenario exists in **GBP** (country
`GB`), **USD** (`US`) and **EUR** for every euro-area country (`DE`, `FR`, `IE`, `NL` and the
others), each with its own productCode. Each test product has a single market, so `country`
is optional on its order lines.

**Mixed partial:** order a success and a failure product in one request to get
`partially_completed`.

**Your catalog products:** any product returned by `GET /v2/catalog/products` can
also be ordered in sandbox; codes are still test-only.

### Find the test productCodes

Test productCodes are specific to the sandbox. Read them from either endpoint:

- `GET /v2/catalog/products?brand=Kalixo%20Test` returns them as normal catalog rows.
- `GET /v2/sandbox/scenarios` (**Sandbox** in the [API reference](/api-reference/introduction))
  returns each product with its expected outcome and a `sampleOrderLine` you can send to
  `POST /v2/orders` as-is. It returns `404` on the production API.

```bash
curl "https://sandbox.kalixo.io/v2/sandbox/scenarios" \
  -H "x-api-key: $KALIXO_SANDBOX_API_KEY"
```

```json Response (shortened, example values)
{
  "products": [
    {
      "productCode": "10999000412573",
      "name": "Kalixo Test - Success (Fixed)",
      "price": 499,
      "currencyCode": "GBP",
      "denominationType": "fixed",
      "isSandboxProduct": true,
      "expectedOutcome": "completed with SANDBOX-* test code(s)",
      "sampleOrderLine": { "productCode": "10999000412573", "quantity": 1, "price": 499 }
    }
  ],
  "note": "Kalixo Test products appear in GET /v2/catalog/products alongside your assigned catalog. All sandbox orders return SANDBOX-* test codes only."
}
```

## Wallet

If wallet ordering is enabled for your account, sandbox orders **debit your sandbox
wallet** the same way production would. They never touch your production wallet. Top up
your sandbox balance through your account manager if you need to test low-balance behaviour.

## Getting started

1. Obtain a **sandbox API key** (`kal_test_…`) from your account manager.
2. Point all requests at `https://sandbox.kalixo.io/v2`.
3. Call `GET /v2/sandbox/scenarios` to list test products.
4. Follow the [Quickstart](/quickstart) - place an order, poll until
   `completed`, and read the `SANDBOX-*` codes from the response.
5. When you are ready to go live, switch to `https://api.kalixo.io/v2` and your
   production key (`kal_live_…`). Catalog `productCode`s of your assigned products are
   identical in sandbox and production, so the codes you integrated against keep working.
