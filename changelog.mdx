## 2.4.0 - 2026-11-11

### Responses

- Every response now carries an `X-Request-Id` header, errors included. Send your own
  `X-Request-Id` to have it echoed back. Include it when you contact support. See
  [Errors](/concepts/errors#request-id).

### API reference

- Documented `GET /sandbox/scenarios`, which lists the Kalixo Test products, their expected
  outcomes and a sample order line. Sandbox only.
- Documented `isSandboxProduct` on catalog products, and `descriptionHtml`, `tncHtml` and
  `redemptionInstructionsHtml` on `languages[]`. The API already returned them.
- Documented the rate-limit headers and `429 Too Many Requests` on every endpoint.
- `POST /orders`: request examples with `country`, and the exact idempotency behaviour.
  Repeating an `externalOrderCode` returns `202` with the existing order and its current
  `status`. `409` happens only when two requests with the same new code arrive at the same
  moment.
- `promotion*` and `serviceFee*` product fields are marked as planned. The API does not
  return them yet.
- Fixed examples: a `failed` order's `reason` is `Order could not be fulfilled`, and
  `processing` and `failed` orders include `wallet`.
- Wallet `balances` and `threshold` are documented as decimal amounts in major units
  (`196.01` is GBP 196.01).
- The production base URL `https://api.kalixo.io/v2` is final.

### Documentation

- [Regional products](/concepts/order-lifecycle#regional-products): when and how to send
  `country`. The quickstart and the Node client now send it.
- [Idempotency](/concepts/idempotency) rewritten. Polling example with a maximum wait and
  retries for `5xx` and network errors.
- [Sandbox](/concepts/sandbox) lists every test product, price and currency.
- The [Node reference client](/examples/kalixo-node) is plain JavaScript again (it contained
  TypeScript syntax) and retries `5xx` responses.
- New guide: [Checkout and Distribution](/checkout/guides/checkout-and-distribution), to take
  the shopper's payment with Kalixo Checkout and deliver the codes with this API.

## 2.3.0 - 2026-08-04

### Catalog

- Which products your catalog lists now depends on your account's catalog setting, which
  Kalixo configures (default: local):
  - **Local:** each product is sold in one country, with its own productCode.
  - **Regional:** one productCode covers a region, for example Europe or the euro area. It
    is listed once for every country in the region that your account sells to.
- A regional product lists every country in its region that your account sells to, even
  when Kalixo fulfils that country from another market's stock in the same region. Kalixo
  picks the fulfilment source for each order.

### Orders

- `POST /orders` accepts the productCodes your catalog lists, local or regional, according to
  your account's catalog setting.
- Lines for a product with more than one country in `availableCountries` still need
  `country` (or a market `sku`).

## 2.2.0 - 2026-08-03

### Catalog

- `GET /catalog/products` now returns **one row per country** for multi-country
  (regional) products. Rows share the same `productCode` and differ by
  `countryCode`, `sku`, and localized `name` / `image` (English fallback when a
  translation is missing).
- New fields on each product row: `sku` (`{CC}-{LL}-{productCode}`) and
  `availableCountries`.
- `GET /catalog/products/{productCode}` accepts optional `?country=` to select a
  market row.
- Rows are limited to countries your account can order.
- The catalog listed regional products only. Since 2.3.0 this is an account setting.

### Orders

- Order lines accept optional `country` (ISO code). For multi-country products,
  pass `country` or a market `sku` so fulfilment resolves the correct market.

### Breaking API changes

| Change | Before | After |
| --- | --- | --- |
| Catalog list shape | One row per `productCode` | One row per `productCode` + `countryCode` (same `productCode` may repeat) |
| Order lines for multi-country products | No country needed | `country` or a market `sku` required (`400` otherwise) |
| Products listed | Every product | Regional products only (an account setting since 2.3.0) |

## 2.1.4 - 2026-07-16

### Products and orders

- Products are identified only by `productCode`, in the catalog, on order lines and in
  order responses.
- `orderId` is a UUID. `GET /orders/{reference}` accepts the UUID or your
  `externalOrderCode`.

### Breaking API changes

| Change | Before | After |
| --- | --- | --- |
| Order line product | `orderProducts[].productId` (number) | `orderProducts[].productCode` (string) |
| Product id | Numeric `id` on catalog products | Removed - use `productCode` |
| Order line in responses | `products[].productId` | `products[].productCode` |
| Order id | `orderId` integer (for example `59400`) | `orderId` UUID string (for example `b9f6f9a2-4d0a-4f5c-9a1e-7c2d8f3b6e10`) |
| `GET /orders/{reference}` | Numeric order id or `externalOrderCode` | UUID `orderId` or `externalOrderCode`; numeric order ids are not accepted |

## 2.1.3 - 2026-06-06

### Ping

- Added `GET /ping` — returns `{ status, timestamp }` to verify API connectivity.
  Requires `x-api-key` and a whitelisted IP address.

## 2.1.2 - 2026-06-06

### Catalog

- Replaced ambiguous `discount` on catalog products with explicit
  `discountAmount` (minor units) and `discountPercentage` (commission rate).

### Breaking API changes

| Change | Before | After |
| --- | --- | --- |
| Catalog discount | `discount` (mixed meaning) | `discountAmount` + `discountPercentage` |

## 2.1.1 - 2026-06-06

### API reference

- **Retrieve order → partially_completed** response example now explicitly includes
  `products[].codes` for all delivered units (not only `delivered` / `total`).

## 2.1.0 - 2026-06-06

### Order behaviour

- `partially_completed` responses include `products[].codes` for every delivered unit,
  alongside `delivered` and `total`.

### Catalog

- `redeemable` is derived from `countryCode` (e.g. `GB` → `United Kingdom`), not the internal region field.
- Documented planned `promotion*` fields on catalog products (see [Promotions](/concepts/promotions)). Not returned yet.
- Documented planned `serviceFee*` fields on catalog products (see [Service fee](/concepts/service-fee)). Not returned yet.

### Breaking API changes

These apply to all v2 catalog and order responses:

| Change | Before | After |
| --- | --- | --- |
| Redemption codes | `products[].pin: [{ pin: "…" }]` | `products[].codes: [{ code: "…" }]` |
| Product tags | `"bestseller,gaming"` (string) | `["bestseller", "gaming"]` (array) |
| Removed fields | `rrp`, `rrpCurrency`, `state` on products | Omitted - use `price` and `status` |

### New validation

- If you send a top-level `price` on `POST /orders`, it must equal the sum of
  `(line price × quantity)` or the request returns `400` with
  `Order price mismatch: expected total {n}`.

### New response headers

All v2 responses now include:

- `X-RateLimit-Limit`
- `X-RateLimit-Remaining`
- `X-RateLimit-Reset`

`429` responses still include `Retry-After`. See [Rate limits](/concepts/rate-limits).

### Documentation

- Fixed polling example to respect `estimatedReadyAt`.
- Added guidance for `partially_completed`, sandbox, webhooks (coming soon), and cancellation.
- Multi-line order pricing example.
- Reference Node client in [examples/kalixo-node](/examples/kalixo-node).

## 2.0.0 - initial release

- Async ordering with `POST /orders` + poll `GET /orders/{reference}`.
- Catalog filtering and pagination.
- Wallet endpoint and embedded wallet snapshots on orders.
- API-key authentication (`x-api-key`).
